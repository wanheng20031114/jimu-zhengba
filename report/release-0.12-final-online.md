# 0.12 联机验收：短时表现改为可丢弃后，极端对照功能通过

**最新 `release_ephemeral1` 七个实际 Game、同一世界 500 单位持续对照完成 385/385 项功能检查，全部观察至少 42 秒，没有原生连接错误、脚本错误或重连。** 六名客户端实收基本公平，可靠指令、通知与结算保持正常。极端负载下仍只有约 3 Hz 快照、约 1.1～1.2 秒最大间隔，不能称为高负载流畅。

用户随后明确将目标收窄为**轻量化、500 单位，之后不需要七人游戏**。因此本报告保留已经完成的七进程结果作为极端诊断，后续不再增加七人测试，也不以七人 15 Hz 作为 0.12 发布门槛。正常较少玩家的最终发布包检查由发布收据另行记录，不能从此极端样本反推其帧率。下方上一轮 FAIL 原文和 JSON 数据完整保留。

产品提交 `c402626` 将短时战斗表现移出可靠重传队列，客户端到中继及中继到客户端两跳均使用原生可丢弃分片；命令、通知、暂停、结算等权威消息仍可靠。没有降低伤害、死亡或经济模拟频率；最新状态快照负责持续恢复实际世界状态。两跳 flag、旧客户端与丢包边界的本地检查见 [表现可靠性验证](release-0.12-visual-unreliable.md)。

新 case 开始 UTC **2026-09-10 17:44:42.239157**。Windows 4.6.3 官方 release EXE 与前轮相同，PCK 为 `bfa5c07699ee60786c63636a2f521aac78c0db1887f53c6d3297d7774c1b5ce3`，包含明确的诊断 autoload；driver、500 单位压力设置与墙钟 profiler 保持同一版本，计时包装正确透传新增 unreliable 参数。客户端与中继均含本次改动，不能拆分估计两跳各自贡献。

## 逻辑推进、计时与剩余性能限制

房主实际推进 **1221 tick / 42.170 秒，即 28.954 TPS**；不是精确 30 TPS，略低于夹具29 TPS诊断目标。全部500个单位存活，真实伤害 **10578 次**、采矿 **529 次**；120条远端命令被房主接收，每名客户端20条命令、20条可靠通知，结算正常。

进程时间12～32秒内的完整19个统计窗口为20.831秒：**101个呈现回调机会，即4.85 Hz**，帧墙钟 P50/P95/P99 为 **216.263/298.017/301.160 ms**。这是同机七个 headless Game 加计时包装的主循环，**不是离线渲染 FPS，更不能替代离线35.29→38.74 FPS的ABBA结果**。

该段物理信号跨度平均26.780 ms/步，Game process35.448 ms/帧，快照组装21.480 ms/批、paced drain10.640 ms/次；后台 JSON21.680 ms/任务、等待0.032 ms。计时范围包含嵌套/并发，不能相加。与早期七端诊断相比，收到的数据量、模拟/视觉工作及同机调度发生变化，缺少单变量ABBA，不能将某一差值全部归于传输flag，也不能宣称这个改动提高了极端主循环频率。

这一轮明确改善的是**持续连接与公平交付的功能结果**，而非七人500单位的目标帧率。按用户新范围停止扩展七人压测，保留上述实值，不据此扩大对普通联机性能的承诺。

## 中继与清理

只读服务观察中没有 engine errors、rejected、snapshot/visual/notice soft-drop，也没有对局中的 disconnect/resume；7次断开均在房间正常结束之后。服务invocation保持、重启0；socket drops0→0，UDP InErrors/RcvbufErrors/SndbufErrors增量全0。完整60秒观察服务CPU14.69秒，含准备/结束/空闲，不能作稳定单核占用率。该场不复现前轮原生发送错误，但单次42秒不等于任意网络条件永久稳定。
