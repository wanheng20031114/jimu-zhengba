# 0.12 最终发行前七人 500 单位复测：未通过

更新中继为官方 release 模板并逐接收事件刷新后，**本次公网七人、同一世界 500 单位对照仍失败**。七个客户端均在目标 42 秒之前因连接状态中断停止观察；最早一名玩家约在比赛开始后 8 秒出现原生错误。中继没有触发此前的限流，也没有本轮 socket/内核接收溢出增量。不能将本地发送积压修复推演为公网整链已经稳定，不能把这一包标成联机性能验收通过。

## 数据身份

运行标签 `release_relayfixed1`，启动 UTC `2026-09-10T17:25:02.044476+00:00`。沿用上轮 `release_threaded1` 的原封不动客户端：产品 `eca8ff9`、诊断 PCK `77f85735cda3dec898bc10958569d4519ba6f71d88d692c258436130bd247bdd`、官方 Windows 4.6.3 release EXE `91724f15024a3a545e28ccd83134403d31ce2323a38e51c95e4dfa282f732ab6`；驱动哈希同为 `c60a8b7d0b69d18e969fe93995dd03a34faa81c4e035096b3a87ee3786208ecd`。

七个实际 Game 共用一台 Windows 主机，4v4 七真人加一 Bot 席位，压力准备后 Bot 战略停用，500 混编单位 HP×100 保持真实战斗和采矿，普通联盟视野仍生效。全端实际确认 release=true、editor=false、debug=false。它们是带计时插桩的 headless 进程，不能当作 Vulkan 渲染 FPS。

## 首个故障与后续事件

服务器开始比赛 UTC **17:25:05.849828**，首次 owner 6 `transport_disconnect` 在 **17:25:13.895639**，相隔约 **8.046 秒**。该客户端进程 msec 9228 记录 `native_error`，最近有效接收仅过去 **166 ms**。服务器第一条 DTLS `-30464` 在 **17:25:13.928923**，晚约 33 ms；不能把后发握手错误直接认定为最初原因。

接着 owner 4、2、3、5、1 和房主均出现传输断开或原生错误。房主自身在 msec **18079** 记录 `native_error`，最近有效接收 **72 ms**，stderr 有四条 `Sending failed!`（原生 `enet_socket_send`）；owner 5 有一条同类警告。不是应用无消息超时，具体原生失败链仍待定位。

房主 msec 19650/19651 已重连回 lobby/match；最终 30.905 秒的 `match_finished` 是测试夹具结束流程，不是初次掉线。`room_required` 仅在房间结束后的两条 `leave` 出现（UTC 17:25:34.418566／34.419645），fatal=false，属于尾声反馈，不能倒置成最初掉线原因。

## 中继边界：限流、队列与收件公平性

本轮服务在观察前后保持同一 invocation、重启次数 0。socket drops 为 0→0；全机 UDP `RcvbufErrors` 和 `InErrors` 仍为 6891，没有增量；`SndbufErrors` 为 0。1 秒采样不能捕获全部亚秒队列峰值，但累计错误不变可排除本轮已计入这些计数器的溢出。此结论不等于 Windows 客户端或 ENet 内部缓冲也没有丢包。

17:25:16～21 的服务频道计数，对 owner1～6 分别为 **33、33、32、32、32、32**，已不复现早先末两位几乎收不到的服务入口偏斜。这是已收到并归类的频道包，不等于全部通过目标路由或最终客户端投递数，断线的接收者也会影响后续发送。

七个统计窗口的 snapshot/visual/notice soft-drop 均为 0。唯一两条 rejected 是上述房间结束后的 `room_required`，没有 rate_limit。完整 60 秒只读观察累计服务 CPU **19.42 秒**，含启动准备、失败对局、重连、清理及空闲，不能用它计算稳态对局单核利用率。网卡计数为整机范围，不把其流量全算作本房间带宽。

## 验收结论与过程清理

本轮证明中继局部修复未能覆盖全部公网传输问题，应继续定位原生错误与转发链，不扩大性能成功声明。[逐事件刷新机制证明](release-0.12-relay-flush.md)仍是独立的有效局部证据；它本来就没有保证公网任意突发必达。

客户端 EXE/PCK 校验前后不变。runner 在已有失败后终止仍未退出的自有 helper；七个 PID 最终均退出，收据和 CIM 核实仅用户编辑器 PID36624 保留。授权线上服务继续运行，未因本报告停止。原始失败记录未覆盖，本报告没有修改游戏、服务器或诊断包，也没有新增测试进程。
