# 积木争霸 0.9.0：八人联网与空位验收

本报告记录本地隔离中继上的原生 Godot ENet／DTLS 验收。游戏版本 **0.9.0**，协议 **8**；客户端 Godot 4.6.3，中继 Godot 4.7.2。全部列出的 **1,660 项检查通过**。完整、脱敏的逐客户端结果与生产源码 SHA256 见 [network-0.9.0.json](network-0.9.0.json)。报告不包含服务器地址、房间邀请码、重连 token 或证书私钥。

## 对局规则与实现边界

- 4v4 有八个席位、两个阵营，每阵营最多四名参战者；允许 4v2、3v1、2v2 等不满员且不对称的阵容。
- 八人乱战每个席位为独立阵营；也允许只使用部分席位。
- 至少两方实际参战，房主必须是真人。仅检查实际真人的准备与连接状态；Bot 无需准备，空位无需填充。
- 参战配置始终保留完整席位数组，`owner_id` 等于席位索引。空位使用 `controller="open"`；移除第五、第六个参战者不会把末席玩家的 owner 7 压缩为其他编号。
- 空位没有基地、免费箭塔、农民、金币、Bot、自然收入或视野，不参与胜负。空阵营不重复计算迷雾网格，既有阵营索引保持不变。
- 真人断线仍保留同一席位，10 秒后由 Bot 接管，120 秒内可认证重连。空位不会创建重连会话，也不能通过伪造事件或快照激活。
- 阵营出生区分别分配，队伍调整和空位不会使盟友进入另一阵营的出生区。
- 第七、第八阵营拥有独立的原生碰撞层；全部 8×8 敌我部队／建筑筛选组合覆盖。
- 房间与中继共同使用 `NetworkProtocol.room_start_error()`。未准备、缺少对手、队满等正常反馈不会累计恶意包次数导致房主被断开；原发送速率、消息尺寸、伪造状态与畸形消息限制继续生效。
- 场景载入失败可返回明确错误，清理本次配置并允许在大厅重新尝试。

## 网络测量

快照仍由 30 TPS 房主每两步发送一次，每个接收者目标为 15 Hz；七个客人分到两个相位，每步最多四个快照。房主到中继使用独立通道 **2～9**，加控制／事件共 **10** 通道；中继到每个客户端使用其连接的通道 2。

保留既有防护边界：**每快照 512 KiB、65,536 个基础值、最多 1,536 个可见实体**；八人全容量快照只需要 25,637 个基础值，无需扩大解析预算。实测未压缩快照 257,908 字节，Zstd 后 8,222 字节，单次权威编码 13.281 ms。压缩率来自该合成数据，不能推算任意实战的带宽。

弱网转发器只转发不透明 DTLS 数据，不解密、不改证书、不改游戏数据。每条**客户端与中继链路**设置 150 ms RTT、±40 ms 抖动、4% 数据报丢包概率、8% 额外乱序概率和 90 ms 额外乱序延迟。客户端经中继到房主还需跨另一条链路，不能把 150 ms 理解为完整客户端—房主往返延迟。

| 八客户端场景 | 实测观察窗口 | 数据报实际丢失率 | 正常阶段快照间隔 P95（七名客人范围） | 房主上行平均 | 客人下行平均范围 |
|---|---:|---:|---:|---:|---:|
| 4v4，本地零损转发 | 32.985 秒 | 0% | 88～104 ms | 134.84 KiB/s | 11.96～20.12 KiB/s |
| 4v4，弱网 | 44.516 秒 | 3.914% | 172～218 ms | 109.34 KiB/s | 9.29～14.39 KiB/s |
| 八人乱战，弱网 | 52.047 秒 | 3.847% | 153～169 ms | 81.51 KiB/s | 6.60～11.53 KiB/s |

快照间隔排除故意断线／接管阶段，稳定阶段持续 15 秒；它衡量状态到达间隔，**不是画面 FPS 或指令延迟**。本地乱战首次功能验收未采集间隔／流量，故没有虚构对应测量值。

字节数是转发器 `recvfrom` 边界记录的 **UDP 负载**，包含 DTLS／ENet 和控制消息，不含 IP／UDP 包头；均按完整观察窗口求平均，包含握手、重连和故意断线。每条链路单独记账，同一游戏状态经房主上行和接收者下行会分别计数。末席断线时间较长，因此其完整窗口平均下行较低。这些数值不能视为满军队会战的持续带宽。

弱网 4v4／乱战分别记录 9／6 次原生 DTLS 握手乱序诊断，均为测试明确允许的 `-30464`，连接随后按原重试机制成功建立；没有脚本错误，也未关闭证书验证。数据报送达、丢弃和退出时清空的待发数据之间的字节账目一致。

## 复现与清理

```powershell
python tests/network_runner.py multiplayer
python tests/network_runner.py empty-slots
python tests/network_runner.py six-codec
python tests/network_runner.py commands
python tests/network_runner.py game
python tests/network_game_live_runner.py local --mode 4v4
python tests/network_game_live_runner.py local --mode ffa
python tests/network_game_live_runner.py impaired --mode 4v4
python tests/network_game_live_runner.py impaired --mode ffa
```

`six-codec` 是既有测试入口名称，本版内容已覆盖八人。发布包的原生对局探针可结合 `--4v4 --match-empty-slots=5,6` 验证六名 Bot 的 4v2 对局；这些参数仅在显式 `--match-smoke` 验收入口生效。

本组测试使用临时本地中继，未使用公网房间。测试 runner 负责关闭客户端与本地中继、终止透明转发线程并移除临时私钥；完成后另以进程命令核实本组辅助 Godot 进程为 0。公网服务部署和最终发布包的验证由发布记录单独说明。
