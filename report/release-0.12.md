# 积木争霸 0.12：五百单位优化与联网收尾

本版按最新要求聚焦 **500 单位下的可玩性与较少真人的正常联机**，不再扩展七人压测，也不以 896 单位或稳定 60 FPS 作为本版已经达成的结论。兵种、建筑、科技和人口规则沿用当前版本。

## 本版投入的优化

- 六类单位使用原生刚体部件批量提交，复用网格与材质，保留原模型的动画与攻击时间轴。静止单位减少不必要的避让提交；导航查询省去未使用的路径元数据，缓存地图迭代版本。
- 权威实体每批统一采样，并复用公共 JSON 片段。一个原生 `WorkerThreadPool` 任务承担批量 JSON 编码，主线程不等待尚未完成的任务；暂停、断线、换局或结束后的旧结果会失效。场景退出时回收任务。
- 按墙钟产生最新快照，避免物理追帧集中发送；每名接收者只留最新待发状态，每显示帧至多三个接收者，共享 48 KiB 实际编码预算，表现队列独立公平重试。
- 短时音效、弹道和命中特效在两跳均采用不可靠分片，丢失时不重传旧表现。命令、暂停、通知和最终结算保持可靠，生命、存亡、金币及伤害由权威状态同步。中继按验证后的消息类型选择传输方式，不信任来包标志。
- 中继改用官方 4.7.2 正式模板；每处理一条收包及时刷新转发。保留证书验证、权限、序号、内容指纹及完整数据校验，并按房主实际接收者数量分配发送预算。

**共享流场、静态扫掠快路径和蒙皮候选保持关闭。** 对照未证明它们在所需场景稳定优于原生路径，部分密集改向长尾还存在退步。

## 已有性能依据

Windows 官方 4.6.3 release 模板、i9-10900KF / RTX 3080、1600×900、Forward+。同包 ABBA 的 500 单位持续混编交战中，原始模型平均 **35.29 FPS**，批量模型与静止剪枝组合平均 **38.74 FPS**，逻辑约 **30 TPS**。这是描述性增幅约 9.8%，**不是稳定 60 FPS**。

该夹具把生命提高以保持 500 个单位持续交战，仍执行攻击、动画、投射物、音效、视野与采集；不是正式数值下的整场比赛，也不是多人联机的渲染 FPS。GPU 平均约 3 ms，当前继续优化的主要方向仍是 CPU 工作。单独静止剪枝的 FPS 收益尚未证明。完整场景、逐项开关、帧尾、路线与背景进程边界见 [性能报告](release-0.12-performance.md)。

## 网络证据与边界

本地原生 ENet/DTLS 的 7/8 人传输、旧客户端兼容与受控丢包验证 **479/479 通过**。实际丢弃 411 个加密数据报，允许缺失表现批次；命令、暂停、通知、最终结果及击杀统计完整恢复。这里只证明传输语义和兼容性，伤害与表现分离另外经过实际游戏代码审查。[详细记录](release-0.12-visual-unreliable.md)

先前七人诊断曾出现明显停更和原生断线，失败记录完整保留。最后已完成的一轮 500 单位、七个诊断游戏进程持续 42 秒，**385/385 功能检查通过，无断线、重连或脚本错误**；但实际收包仅约 2.93～3.00 Hz，最大间隔约 1.2 秒，不能称为七人流畅验收。按用户随后收窄的范围，不再追加这一规模的测试。[完整前后记录](release-0.12-final-online.md)

## 中继与回退

线上中继使用正式模板，发布目录 `4b53ad5b01390aa8`，协议10、8房、每房最多8席位；容量不代表所有满房并发已经通过性能验收。服务器实际记录 `editor=false / debug=false / dedicated_server=true`。现有公开证书、私钥身份、UDP24571及另一应用UDP24570服务保持一致；更新时先确认无在场玩家，上传后、切换前再次检查。

部署工具验证官方运行时、源码收据与包体哈希，将 EXE/PCK 配对放在不可变版本目录。配置半写或启动失败会恢复旧配置、服务单元和发布路径。原34项审查及4项回滚检查见 [部署安全报告](release-0.12-deployment-safety.md)；新增空闲复查后的38项离线故障注入也通过。

修改前的源码快照和主工作区原有22份文件已单独保存；正式构建与诊断构建分目录，运行中的用户编辑器和正常游戏不属于测试进程。
