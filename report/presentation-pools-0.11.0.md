# 0.11.0 弹丸与特效资源复用

本项负责限制战斗表现对象的数量与重复创建，不将独立优化归因成整场 FPS 提升。整场 CPU／GPU 归因与最终帧率由本版本性能报告记录。本项验证使用 Godot 4.6.3 无头模式，不能衡量最终 GPU 画面成本。

## 实现

### 弹丸

- 新增原生 `projectile_pool.tscn`，预放置 64 个可编辑弹丸实例。忙碌时每批增加 16 个，最多 256 个。所有实例共用原有 mesh 与 material 资源。
- 伤害与模型容量分离。每次攻击均有一份 `ProjectileFlight`，沿用 30 TPS 权威步和发射时的攻击快照；视觉池耗尽只省略多余的箭／炮弹模型及尾迹，每发逻辑弹丸仍然飞行、命中。
- 轻量飞行记录同样复用：初始 64 份，忙碌时按需增加，空闲缓存最多保留 1,024 份。活动记录没有这个上限，因此缓存满不会丢伤害。
- 炮弹、箭矢继续追踪已锁定目标；投石继续使用固定落点、半径 3 的无边缘衰减溅射。投石查询共用一个原生 SphereShape3D 与 PhysicsShapeQueryParameters3D，按本次攻击阵营设置碰撞层。
- 独立加载 `projectile.tscn` 的既有战斗 fixture 仍保留原生命周期，和生产池共用同一个 Flight 伤害内核。没有第二套针对测试或客户端的伤害实现。
- 模型保留命中后的最终姿态一个固定步，再归还，保证最后一段物理插值。复用时清空炮烟、旋转和旧姿态；空闲记录清空攻击者、目标、攻击快照、世界、画面节点引用。
- 池内先推进，之后再统一回收和压缩。命中回调若结束比赛，只记录待清理状态，本次回调完成后终止剩余批次并清理；出手观察信号同步取消时，返回空结果，Game 不广播已经取消的弹丸。
- 暂停使用原生场景暂停，客户端弹丸只表现。结束、重开、退出均接入 `reset_all()`；场景树退出也会清空仍在外部被观察的 Flight 引用。

预加载增加一小块固定场景开销，换取常规交战期间复用；极端齐射超过 256 个同时飞行模型时，画面细节有明确上限，而权威伤害不中断。这里没有把整场单位逻辑绑定到可见性，也没有关闭隐藏单位的战斗模拟。

### 特效

- 保留原有 128 个原生特效实例及原来的独立声音池。
- 小型命中火花、木石碎屑与尘土按 64 像素屏幕格合并：同格 100 毫秒内最多激活一次。位于视口外的小型效果不占用实例。
- 爆炸、建筑坍塌和移动／攻击指令标记不受这层密度过滤。特效池满时，重要反馈优先替换小型效果；新反馈仍能显示。
- 火花、尘土、碎屑和弹丸尾迹不再投射阴影。模型与建筑的阴影不在此变更范围内。
- 声音仍由 Game 在调用视觉池前交给独立混音池，视觉合并或回收不会截断声音尾音。

没有直接将已有 CPUParticles3D 整批替换成 GPU 粒子；那会改变瓶颈分布，必须结合真实 GPU 测量再判断。Godot 文档也明确指出，降低 GPUParticles3D 的 `amount_ratio` 并不能降低其分配与处理成本，因此本项真正减少的是激活的效果数量。[Godot 粒子接口](https://docs.godotengine.org/en/4.6/classes/class_gpuparticles3d.html)

原生 mesh/material 复用有利于 Godot 复用绘制资源；透明几何仍有额外成本，不能因为对象池存在就推断 draw call 或 GPU 成本已经消失。[Godot 3D 性能文档](https://docs.godotengine.org/en/4.6/tutorials/performance/optimizing_3d_performance.html)

## 验证

| 检查 | 通过 | 内容 |
|---|---:|---|
| 临时池生命周期专项 | 22 / 22 | 320 发及 1,100 发齐射、画面上限、伤害完整、双池复用、引用清理、炮烟复用、暂停、客户端、受击结束、出手取消、场景退出 |
| 现有 effect_pool_test | 45 / 45 | 固定池上限、屏幕格合并、视口过滤、重要效果保留、粒子及 tween 回收 |
| 现有 catapult_impact_test | 255 / 255 | 四个所有者、友敌碰撞层、单位／建筑／工地、边缘完整溅射、发射后攻击者被删除、原生攻击动作释放 |
| 合计 | **322 / 322** | 三次最终运行 stderr 均为空 |

临时专项总共发射 1,760 次；峰值同时逻辑弹丸为 1,100，峰值画面实例为 256。两批超出画面上限的齐射和后续用例共省略了 972 个视觉借用，全部仍走逻辑结算。1,100 发单批命中逐项计入了目标的实际受击计数，退出后外部保存的 Flight 也不再持有目标或世界引用。

原先根据 `Effects` 子节点数量或 `child_entered_tree` 观察弹丸的现有测试，已迁移到池的真实发射信号、活动 Flight 与画面计数；两个现有压力工具也区分逻辑弹丸、活动画面和预加载容量，不会把 64 个空闲预实例当成正在飞行的弹丸。

第一次临时测试的两条 WeakRef 局部变量缺少显式类型，触发项目“警告视为错误”规则；补齐测试变量类型后重跑通过。没有通过忽略脚本错误来获得通过结果。

完整脱敏数据见 [presentation-pools-0.11.0.json](presentation-pools-0.11.0.json)。测试辅助 Godot 进程 PID 45080、44936、27936 均自行正常退出，随后通过 Win32_Process 按相应测试命令核实无残留；用户编辑器未操作。

临时源码没有加入版本控制。归档后尝试仅删除 `.local/perf0110` 下本次 `pool_lifecycle_*` 源码／结果及 `pool_lifecycle.*.log`、`effect_pool.*.log`、`catapult_pool.*.log`，命令在执行前被自动审批以 `blocked by policy` 拒绝；没有执行删除，也没有改换方法重试。这些临时文件保留待用户清理，其余性能工具和日志未操作。
