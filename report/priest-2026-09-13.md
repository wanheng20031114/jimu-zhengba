# 牧师v1：建模、治疗与学院试装

2026-09-13，工程兵v2得到用户明确验收后开始本阶段。牧师v1已完成，状态为**等待验收**；重型火炮、三管短炮尚未开始。

## 数值与操作

| 项目 | 基础值 |
|---|---|
| 价格、训练、建筑 | 180金币；18秒；学院 |
| 生命、护甲 | 70生命；近战0、远程1 |
| 移动、视野、人口 | 3.5；14；2军事人口 |
| 直接攻击 | 3近战，挥拳，1.5秒间隔、0.25秒前摇、0.8射程 |
| 分类、半径 | 步兵；0.45 |
| 治疗 | 距离6；首次完整施法0.6秒恢复10生命，后续每1秒恢复10 |
| 消耗 | 治疗免费，无金币或法力消耗 |

右键受伤友军可指定治疗，Shift可排队。支持己方及盟友步兵、弓手、骑兵、农民、工程兵和其他牧师；不治疗自身、攻城器、建筑、阵亡单位或敌人。同一目标同时一个有效治疗者，多个牧师会寻找其他伤员。

自动选择按生命比例、距离、实体编号排序，只治疗已在范围内的目标。手动指定可跟随；正常移动中断治疗；攻击移动可停下来治疗，满血后继续原路线。坚守不追随，手动攻击切换为挥拳。

学院第一页第一个按钮为牧师，科技可翻页；训练与研究分别计时。取消训练退还180金币及2人口预占，建筑被毁释放队列。电脑招募阵容保持原有单位，识别牧师为支援单位；接管现存牧师时安排其在可治疗部队后方行动。

## 模型与动画

编辑入口：[priest.tscn](../assets/models/units/priest.tscn)；分件：[priest/](../assets/models/units/priest/)；战场：[batched/priest.tscn](../assets/models/units/batched/priest.tscn)；作者代码：[unit_priest.py](../tools/unit_priest.py)。

10个刚性分件，3,612个三角面，预算4,500。人体和五官使用现有角色基准。敞口亚麻兜帽与象牙色长袍、金色胸饰、皮革腰带和书袋突出职业；阵营色集中在帽沿、袖口、前后披带。双手空闲，采用两段式袖子。前后袍摆独立运动，使用保存的原生动画，不运行布料物理或实时IK。

待机轻微呼吸，行走短步摆袍；挥拳在0.25秒出手；治疗为双手抬起、向目标伸出并收势的1秒循环，0.6秒对应恢复姿态。两手粒子节点位于各自前臂下，与动作一起移动。目标效果为向上飘散的暖金光点与柔和光晕。

粒子全部采用保存场景中的 `GPUParticles3D`、`ParticleProcessMaterial` 和原生渐变纹理。每手10个光点，每次目标效果18个光点加1个光晕；目标效果复用128槽的既有效果池，生命结算独立于效果池容量。暂停同步停止手部和目标粒子；死亡、隐藏及离开动作时停止相应效果。

三轮实际渲染检查使用Godot 4.6.3 Forward+ / Vulkan、RTX 3080：正背面、左右侧面、四分之三、俯视和面部近景；行走、挥拳、治疗各12个采样；普通/批量模型、图鉴、头像、战场正常与近景缩放、阵营色、学院旁与树木附近、倒地及淡出。检查后修正了肘部袖子间隙、披带穿入胸部和袍摆、兜帽包边断口，并增强治疗光点的可读性。

展示入口：**战争图鉴→牧师→行进／攻击／治疗**。治疗预览自带一名受伤剑士，可以旋转、缩放和暂停。学院可训练，沙盒可放置。当前必要画面保存在被忽略的 `artifacts/model-previews/priest/`，包含模型、图鉴、真实战场和实际渲染的治疗GIF；临时采样帧与已验收工程兵展示图清理后只留本阶段必要图像。

## 共享实现与联机

`UnitDefinition` 增加支援前摇和自动追随配置。`UnitSupport` 同时处理维修与治疗，通过独立 `restore_health` 恢复并钳制生命，不使用负伤害。工程兵仍每秒5生命，不改变旧单位数值。

支援提供者和受治疗目标都保存基于对局时间的下一次恢复时刻。取消、重复点击、切换目标、轮换提供者都不会刷新该时刻；治疗被移动或换目标中断时，必须重新完成0.6秒施法。使用统一时钟还避免了目标和提供者更新顺序缩短恢复间隔。攻击科技仅提升挥拳，主动治疗不重置战地休整的受伤计时。

主机唯一结算生命和支援占用。客户端接收生命、工作状态与原生动画阶段；输入只能决定单位和目标，额外提交的恢复数值不会被用于结算。治疗使用已有的友军支援命令与视觉事件通道，补充 `heal` 动画校验，拒绝兵种与能力不匹配的状态。协议升级为12，内容清单增加牧师及学院招募数据。

本阶段联机检查为匹配内容的本地DTLS协议回归及真实单位场景的主机/客户端快照与动画验证；没有进行线上服务部署或替换已发布安装包。
