# 0.12 表现包预算受阻后的公平重试

基于 `6b91ac1` 的逐帧发送预算发现一个调度遗漏：快照发送成功后即移出待发字典，而该玩家的表现包可能因剩余字节不足返回 `ERR_BUSY`。表现事件仍保留在队列，但调度只遍历待发快照，因此没有下一次独立重试机会。固定分组的尾位玩家可能重复遇到这一情况，直至事件过期。

本次改为调度待发快照与表现队列的并集。因预算受阻的表现包在下一次实际显示帧优先于该玩家更新的快照尝试；游标保持公平轮转，50 ms 单玩家频率限制不会阻塞其他玩家。快照成功后不会为重试表现而再发一次。两类数据仍共享每帧 48 KiB、最多三个玩家的预算，可靠控制与结算行为不变。暂停、换局及断线清理同时清掉表现重试优先级。

全新窄回归共 **172 项通过**。使用真实 RelayClient 编码与 MatchReplication 调度，以及真实连接的原生 ENet peer 满足快照资格；仅最底层发送替换为捕获器。因此它验证调度、编码大小、队列与帧预算，不代表实际 UDP 投递、七人真实 Game 或发布版帧率。

- 单快照编码为 12,127 字节，单表现包 5,138 字节。首帧实际发送 46,667 字节，第三玩家快照成功而表现受阻；下一帧首先重试其表现，快照不重复。
- 没有新快照时，六名收件人的剩余表现全部送完。
- 在约 60 次/秒的真实 process 机会中连续生成八批、每批六名收件人的表现，48 条全部且仅一次送达捕获器；所有发送帧均不超过 48 KiB 和三个玩家。
- 同帧反复调用不会再发送；单玩家 50 ms 限制不会沿用旧的预算受阻标记；换局清理覆盖两类队列及重试优先级。

运行环境为官方 Godot 4.7.2 Windows、headless、BelowNormal，辅助进程已退出，stderr 为零字节，并通过 CIM 复核。原始临时夹具及结果位于根工作区 `.local/release-0.12-visual-fairness-tests/`，本次未删除。源码、夹具及结果哈希见同名 JSON；没有修改中继或协议。
