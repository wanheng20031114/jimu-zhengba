## 同时发现的打包问题

1. **最新包中的地图与随包清单不一致。** 使用 Godot 原生 `ProjectSettings.load_resource_pack()` 读取实际 PCK，按清单生成器相同的 CRLF 归一化规则计算 JSON 哈希，确认 `amber_crossroads_1v1_layout.json` 和 `three_frontiers_3v3_layout.json` 的实际内容已经变化，而清单仍记录旧值。旧 0.12.0 包的地图校验通过。relay 的精简 PCK 本身不携带地图，不对其进行地图实体校验。
2. 工作区的 `spearman.tres` 序列化文本也与清单不同，主要是编辑器补充 UID、调整属性顺序及省略默认值；实际新包中的长矛兵数值校验通过。没有把该文本差异误判为兵种数值损坏。
3. `tools/build_windows.ps1` 当前直接导出，没有在导出前调用 `tools/build_content_manifest.py`。现有包内自检检查资源存在和运行时数值，没有逐一检查地图内容是否匹配清单，所以新包虽然通过 196 项资源检查，仍可能带有过时清单。
4. 最新 EXE 的 Windows 文件/产品版本为 `0.11.0.2`，代码的发行版本为 `0.12.0`，网络 Build 为 `0.11.0`。这些标识含义不同，不能仅看文件版本判断是否能联机。现有发行说明也仍描述旧阵容和旧数值。
5. `tests/network_release_runner.py` 仍要求恰好 75 项资源数值检查；新包实际已执行 90 项。此次直接读取实际 EXE 的 `NETWORK_RELEASE_PROBE` 结果，避免该过时断言产生误报。
