# 积木争霸 0.11.0.2：多人个人击杀结算修复

日期：2026-09-10。

## 问题与修复

旧逻辑只在房主的 `Game.kills` 中累计房主阵营的敌军死亡数量；玩家状态没有个人击杀数，快照与可靠结束消息也没有传递统计。因此非房主的结算一直显示0，房主则可能把队友的击杀也算到自己名下。

现在由房主在单位死亡时，根据致命一击的 `owner_id` 为对应玩家增加一次击杀。实时HUD和结束HUD均读取本地玩家的统计。敌方农民与军事单位计入击杀，建筑仍属于独立的摧毁统计；友军、自毁和淘汰清场不计入击杀，助攻不重复归分。

弹丸使用出手时已有的 `DamagePayload.owner_id`，因此骑士、炮手等攻击者死亡或节点释放，不会失去在途弹丸的击杀归属。单位只在致命一击记录归属，不复用此前非致命攻击者，避免受伤单位随后自毁时错误给分。

玩家自己的击杀数随已有私有快照发送，未加入其他玩家的公开实时状态。对局结束时，房主通过现有可靠结束消息发送所有席位的最终击杀数组；客户端在打开结算面板前应用它。结束后的快照接收与插值停止，避免旧快照覆盖最终分数和用时。

计分字段必须为非负整数，最终数组长度必须与已有房间席位一致。校验不依赖开局消息填充的状态，避免不同ENet通道使结束事件先到时访问尚未建立的对局字典。更新对旧协议10的缺字段消息保持可连接，但旧房主无法提供新统计；**房主和客户端都应更新至0.11.0.2**。

## 验证

使用正式PCK中的 `main.tscn`、Session、RelayClient、MatchReplication、战斗单位和HUD，在两个原生Godot4.6.3客户端与隔离的Godot4.7.2 DTLS中继间验证。2v2中，房主与客人同队，另外两个席位为Bot；仅为固定击杀情形暂停Bot决策，战斗命中通过真实生产伤害和弹丸代码执行。这是确定性功能验证，不是持续完整对局或性能压测。

共115项检查通过，房主61项、客人54项，0脚本错误、0网络错误、0中继拒绝。

| 检查 | 结果 |
|---|---|
| 房主击杀1个，客人击杀4个 | 最终各玩家为 `[1,4,0,0]`，实际结束HUD分别显示1和4 |
| 客人实时计分 | 收到6个快照，最高只包含3杀 |
| 第四杀与结束在同一回调执行，不发送新的世界快照 | 可靠结束消息正确从3补为4 |
| 结束后注入旧快照并再次调用插值 | 分数保持4，最终用时不回退 |
| 重复攻击已死亡单位 | 不重复加分 |
| 房主助攻、客人完成致命一击 | 只记客人一次 |
| 友军攻击、受伤敌军通过销毁命令自毁 | 不加分，不沿用之前的攻击者 |
| 加农炮发射后死亡且节点完全释放，真实池化弹丸命中 | 击杀仍归发射者所属玩家 |
| 2、4、6、8席的数组；负数、小数、错误长度、字典 | 合法数组通过，非法统计拒绝 |
| 房间已知但开局消息尚未到达，或已正常开始 | 两种状态均接受正确席位长度，拒绝错误长度；不访问空对局字典 |
| 旧协议10消息缺少kills字段 | 仍可接受，不虚构统计 |
| 比赛期间其他玩家的公开状态 | 不包含私有击杀统计 |
| 结束后连接和房间释放 | rooms=0、sessions=0，所有测试进程退出 |

早期候选包首次运行发现两项临时测试预期使用了GDScript严格数组类型比较，JSON数字容器与 `Array[int]` 不相等；修正为按已验证整数值比较。之后对最终包重新执行完整回归，不将旧包的检查结果当作最终包结果。

正式Windows EXE另通过177项发行资源检查；包内版本、说明及内容清单经过核对。最终包在RTX3080、Forward+ Vulkan、WASAPI下实际渲染180帧后正常退出，退出码0，无错误。联网与实际EXE渲染验证使用独立日志，用户正常编辑器保留。
