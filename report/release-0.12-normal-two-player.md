# 0.12 正常 500 单位联机收尾

2026-09-11（北京时间）仅运行一场 **2 真人＋6 原生 Bot、4v4、42 秒**公网验证，**116/116 检查通过**。遵循本轮收窄范围，没有追加七真人测试。

## 场景和边界

- 产品代码精确冻结于 `c4026265302b135d8997844226dc35cb3069ba09`；另用诊断入口驱动官方 Windows 4.6.3 release 模板，确认 editor=false、debug=false。该诊断包不是玩家发行包。
- 初始 500 单位：452 军事单位、48 农民。各玩家给予现有两级人口科技，军事上限100、实占72或73、6农民，均符合正式人口规则；不修改任何数值资源。
- **正式生命值，没有放大、锁血或自动复活。** 仅生成阵容和等待两端准备期间暂停 Bot，开始交战时恢复原来的六个 Bot 对象。观察期按原生 AI、生产、采集和战争迷雾运行。
- 两真人使用默认席位0、1，同属一队；其余六席位均为正常 Bot。两客户端同机、无头，故此结果不作为GPU/渲染FPS验收，也不表示全程500存活单位。
- 保留每两秒一次的正常权威移动命令、私有通知、快照接收及可靠最终结算验证。结束由夹具调用正常房主结算接口，不代表自然清建筑胜负验收。

14.47份/秒是这一场的实测值，未把15Hz设为追加测试或调参目标。客人最多一份快照包含448个可见/许可实体，不对其发送隐藏敌人。

原始500单位阵容记录到198次受伤、1,955点伤害、10次死亡、532次采集完成；观察结束仍有490个原阵容成员存活。正常Bot生产继续进行，房主单位容器的1Hz采样由500增至530个节点；此计数可能含消散中的尸体，不能直接当作精确存活人口。

## Bot 开销

仅给原生 `SkirmishBot._decide` 增加观测，不改变决策频率或算法。排除首个跨越观察起点的日志窗口后，40个完整窗口共记录246次决策：

- 每次决策平均 **1.535毫秒**。
- 各窗口的决策均值范围 **1.358～2.607毫秒**。
- 单次观测最大 **2.892毫秒**。

以上为包含子调用的单调时钟墙钟时间，不是线程CPU时间；六Bot在权威线程运行，不能再与包含它们的game.physics时间相加，也不能将窗口均值范围当作P95/P99。
