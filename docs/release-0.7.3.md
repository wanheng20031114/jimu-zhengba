# 0.7.3：联机死亡引用修复、剑士远甲与投石车调整

2026-09-10；Godot 4.6.3 / Windows x64，协议版本仍为 4。联机双方需要相同的 0.7.3 客户端与资源清单。

## 联机选择生命周期

真实客户端场景复现了“选中骑兵后骑兵死亡，随后刷新 HUD 或 Shift 追加选择”的已释放实例错误。网络快照移除副本后，原选择列表要等最多 0.12 秒才过滤；在此之前，节点已经释放，输入与界面仍读取它。

现在在副本释放前同步清理选择、编队与双击目标缓存。权威死亡也使用同一个本地清理入口；离开战争迷雾的副本不会因此执行死亡奖励、人口变动或死亡音效。完整证据及调查边界见 [闪退调查](crash-investigation-0.7.3.md)。本轮复现并修复的是脚本引用错误，尚无对应玩家转储可证明原生进程退出同因。

另修复了施工目标消失后点击旧“取消施工”按钮的空引用：按钮动作保存稳定的实体 ID，仍由权威命令入口判断目标是否有效。

## 稳定性与诊断

中继心跳超时改用 ENet 正常断开。原生对照验证消除了旧路径的 TLS 握手错误；没有证据将其归为本次客户端报错的同一根因。

发布版日志即时落盘，记录版本、进程、对局生命周期及每 15 秒运行概况。验证工具使用独立日志路径，避免覆盖玩家日志。Windows 包新增 `COLLECT_DIAGNOSTICS.cmd` 与只读收集脚本，收集游戏日志、近期相关 Windows 事件、硬件概况和安装包哈希，在文档目录生成本地 ZIP；不自动上传、不修改设置、不复制内存转储。

原生 Vulkan / WASAPI 四轮交战与重开通过 92 项检查，合计 3472 次伤害、538 名单位阵亡；最后两轮同构 280 人场景返回大厅后内存差为 5320 字节，节点、资源和显存计数相同。这是稳定性样本，不是新的帧率基准。
