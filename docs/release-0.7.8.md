# 0.7.8：每位玩家开局自带弓箭塔

2026-09-10；Godot 4.6.3 / Windows x64，协议版本 4。Windows 客户端与上海中继已同步至 0.7.8。

每位玩家在己方左侧出生矿旁免费获得 **1 座已完工、1000 满血的弓箭塔**。适用 1v1、2v2、真人和 Bot；初始大本营、3 名农民、320 金币保持不变。塔自动攻击、不能驻军，按所属玩家与队伍着色，也计入清建筑胜负。

开局建筑统一由房主创建，普通客户端接收正常建筑快照，不会自行多生成一座。塔位保存在两张地图现有出生标记的 `starting_tower_position` 元数据中，同时同步地图作者脚本与布局数据；没有使用运行时随机找位。

| 地图 | 各出生位塔坐标，X／Z |
|---|---|
| 1v1 琥珀十字路 | (-26, 10)、(26, -10) |
| 2v2 双谷争锋 | (-52, 7)、(-52, -25)、(52, -7)、(52, 25) |

双方保持 180° 镜像。塔不占道路或采矿槽，六个出生位的 36 个采矿位置均可通过实际导航到达，大本营仍能朝矿脉方向训练农民。原有岩树和导航源资源不变，动态建筑导航正常扣除开局塔占地。

本包也包含本轮此前完成的调整：剑士对骑兵 +40 附伤；新建防御塔 150 金币、1000 生命；投石车中心命中无科技剑士造成 79 伤害、弓手造成 50 伤害。详见 [0.7.6](release-0.7.6.md) 与 [0.7.7](release-0.7.7.md)。

| 2v2 四位玩家相同规则及逐塔真实箭矢 | 189/189 |
| 四客户端真实主场景、开局塔同步与重连 | 215/215 |

新增原生测试最初过早检查异步导航的首个出兵口；测试随后按既有生产测试约定，有限等待所有出口发布完成。仅修正测试就绪等待，未据此修改运行时代码或地图。最终两图共 285 项检查均通过。

四客户端使用独立中继，验证每位玩家收到且仅收到一座归自己所有、生命与作者位置正确的开局塔；继续通过原有生产、研究、断线重连和阵亡选择清理流程。实际 EXE 对局以 10 倍模拟速度经过 373.87 秒、288 次伤害和 40 名军事单位阵亡后，正常清建筑获胜并退出。这是自动对局样本，不代表玩家平均时长或胜率。

实际 EXE 公网探针通过 44 个资源、57 项数值检查和 DTLS 握手，但创建测试房间时已有玩家占用唯一房间，返回 `capacity`；公网临时房间流程未完成，未重启或干预玩家对局。房间与开局同步流程已由独立四客户端覆盖。

上海部署 `4718d6dd20d13aed`，UDP 24571 服务正常，协议、资源清单和中继脚本与本地一致；原 UDP 24570 服务保持不变。验收详情、截图记录和最终文件哈希见 [验证记录](validation-0.7.8.json)。

Windows 打包现在只收录 EXE、PCK、玩家说明及两个诊断文件，保持 `windows/` 目录结构，并检查 ZIP 完整性。导出器留下的 `AshenCrown.exe~RF7135e44.TMP` 被排除，避免下载包带上多余的约 100 MiB 副本。自动审批拒绝删除该文件，返回 `blocked by policy`；因此它仍保留在本机构建目录，未进入 ZIP 或 Git。本轮其他文本临时文件归档后清理，验证辅助进程核实退出，用户编辑器保留。
