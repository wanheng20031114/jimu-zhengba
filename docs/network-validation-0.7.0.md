# 0.7.0 联网发布验收

本轮统一游戏版本 `0.7.0`、协议 `3`、Windows 文件与产品版本 `0.7.0.0`，主菜单同步显示 `v0.7.0`。版本入口为 `scripts/network/network_protocol.gd`；清单生成器读取这里的常量，避免单独维护另一份版本。

## 清单与部署

43 项原生资源包含 `data/economy.tres`、六类单位、建筑与科技、两张地图及其地形、自然障碍、导航和布局数据。指纹策略沿用既有方案：文本资源按 UTF-8/LF 规范化，二进制 `.res` 按原字节计算；导出后会转换的脚本由协议与 BUILD 标识隔离版本，不混入逐字节资源校验。最终资源冻结后再次生成的清单未发生变化。

上海独立部署版本为 `d4f9af1e7d0cb65b`，`ashen-crown-relay.service` 使用 UDP 24571。只读审计核实新旧服务均为 `active/running`，重启计数均为 0，分别监听 24571 与 24570。原 `bot-jump-relay.service` PID 270544 在部署前后保持不变；新服务 PID 278843。远端协议脚本、清单和中继脚本与本地逐字节一致。

部署使用既有公开证书与独立运行时。管理凭据仅在部署进程内存中读取，私钥、端点和原始日志保存在忽略的 `.local/network/`。部署记录为 `deploy-0.7.0.log`，只读审计为 `audit-0.7.0.json`。

## 实际对局联机

四个独立 Godot 4.6.3 进程分别运行完整 Game 场景，经原生 ENet/DTLS 通信。测试场景预置完工生产建筑与测试经费；后续生产、研究、移动和攻击全部通过客户端命令、服务器验证及权威模拟执行。

每名普通客户端连续训练两名剑士，逐个等待真实 6 秒，并先预留两个军事人口；客户端观察到训练队列后仍只有原先的一名士兵。两项学院科技按真实 20 秒与 25 秒依次研究，跨越普通玩家与房主的断线恢复后完成。没有修改研究时间、训练时间或全局时间比例。

检查同时覆盖仅所属玩家接收的训练、研究、人口、Shift 任务计划，盟友和敌人不能收到这些私有字段；对迷雾内目标不发送实时状态。重复网络序号、伪造所有权、伪造金币、非法攻击和伪造权威事件均不能生效。普通玩家真正离线 10 秒后由 Bot 接管，恢复后取回控制；房主断线暂停后恢复，所有客户端保留同一场景并收到可靠结算。

本地与公网对局各约 52.5 秒。排除刻意断线阶段，公网三名客户端快照间隔 P95 分别为 72、83、75 ms，最大间隔 134 ms。此处是标准场景的网络间隔观测，不代替既有 280 单位性能报告；本轮没有重复长时间 280 单位压测。

期限边界测试通过移动本机单调时钟期限验证，不声称实际等待了完整 30/120 秒。实际四客户端场景中的普通玩家 10 秒接管等待未加速。

源码发布入口逐项检查 43 项资源、44 项实际数值、公开信任证书、清单、0.7.0/协议 3，并通过上海真实房间创建、开局和结算。Windows 导出包由主任务完成后执行相同入口，结果另行补入。

以上所有测试 stderr 为空。Runner 正常关闭自己启动的四客户端、临时中继及代理，最后的 CIM 检查仅剩用户编辑器 PID 19228；上海生产中继继续运行。
