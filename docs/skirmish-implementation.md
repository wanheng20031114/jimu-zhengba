# RTS 遭遇战实施记录

本文为 0.6 阶段实施历史。0.7.0 已将军事即时生产改为计时队列，并调整采矿；现行规则见 [生产与科技队列](production-queues.md)、[训练节奏与建筑出场](rts-economy-placement.md)、[玩家说明](windows-readme.txt)。

本轮按已批准的遭遇战、四玩家、战争迷雾与 Host 权威联网方案分阶段交付。

## 阶段一：统一战斗数据

- 单位、建筑、科技是 `data/` 中独立的 Godot Resource；生产、HUD 与战斗共用 `BalanceCatalog`。
- 近战与远程护甲分别计算。类别加成只匹配一个战斗类别，攻防科技 I/II/III 总加成为 1/2/4。
- 发射时保存攻击快照，命中时读取目标护甲；攻击者死亡不使已发射弹丸失效。
- 骑士移除额外冲锋伤害；投石固定落点、中心至外圈衰减；炮弹跟踪单体并仅伤害这一目标。
- 玩家状态区分资产所有者和同盟，科技分别持有；单位为后续联机预留权威模拟边界。
- 矿脉有六个原生 Marker3D 工作点，活动任务占位，停止、死亡和销毁释放，未来排队任务不占位。

验证：`balance_matrix_test.gd` 932 项数值断言、`balance_combat_test.gd` 31 项真实物理/单位/弹丸断言通过；主场景启动与完整退出检查通过，日志无错误。

这一阶段保留原地图与原招募入口；下一阶段迁移到通用建筑生产、训练队列与研究面板。

## 阶段二：生产、建造与科技

- 每座建筑保存原生 `Production` 子节点。大本营仅训练农民，兵营即时生产剑士、弓手与骑士，军工厂即时生产投石与炮。
- 农民训练十秒并预留十人上限；取消全额退款，出口堵塞时保留完成状态。军事人口独立上限六十，无法出场时不扣金币。
- 学院支持逐级研究、同玩家项目去重、不同学院并行不同路线、取消退款和被毁损失当前项目。科技作用于既有及未来军事单位。
- 农民建造菜单使用真实建筑模型。保存了玩家兵营、军工厂、学院模型与独立预览视口；建造费用、时间、尺寸统一取自数据资源。
- 人类、Bot 与未来远端请求通过同一命令队列，物理步执行所有权、费用、人口、前置和坐标校验；重复序号不执行第二次。

验证：真实主场景 `production_rules_test.gd` 37 项检查通过，覆盖训练/人口、取消、科技生效、学院摧毁、同盟所有权和重复命令；完整启动退出日志干净。

## 阶段三：遭遇战、地图与战争迷雾

- 新增 96×96 的琥珀十字路与 128×112 的双谷争锋；默认 1v1 对 Bot，四人模式按 owner 独立持有金币、单位、人口及科技。
- 每人以 320 金币、三名自动采矿农民和大本营开局。移除免费敌军增援与拆楼金币奖励。
- 每联盟共享三态视野；隐藏敌军不参与选取、计数、小地图、音效与特效显示。建筑记忆冻结在最后一次发现时，无实时生命值或碰撞体。
- Bot 使用相同经济/命令入口、已侦察情报和小队策略；清除全部军事建筑及工地决定胜负，失去全部已完工核心生产建筑后永久暴露该队剩余及未来建筑。
- 地图采用少量合并静态网格与预制导航格，施工时只修改变化占地；大图寻路显式限制 16384 多边形，避免默认 4096 限制截断跨图路径。

验证：地图107项、迷雾273项、Bot策略107项、两图边界各37项通过。两图分别进行六分钟无注资真实AI对战，首伤约45.5秒/40.8秒，军工、学院、科技均能发展，经济/人口/矿位/施工不变量持续通过。真实Vulkan场景截图、完整退出无错误。

## 阶段四：房间与房主权威联网

- 原生大厅支持单人、1v1/2v2 房间、邀请码、四席位及 Bot 配置；Session 跨场景维护经过 DTLS 验证的 ENet 连接。
- 上海独立中继已部署到 UDP 24571。房主运行 30 TPS 权威逻辑，每位客户端在独立通道接收 15 Hz 可见快照；120 ms 时间线统一插值位置、转向、攻击动作和可靠表现事件。
- 网络命令只接受基础值，按连接绑定所有者；整型编号、序号、资源、人口、同盟与可见性都由房主校验。隐藏敌军、其他玩家的经济与研究进度不发送给普通客户端。
- 加入内容版本指纹、跨局标识、流量限制、可靠结算、房主暂停/重连和普通玩家 Bot 接管。联机 Esc 是本地菜单，P 由房主统一暂停，F12 仅单机可用。
- 大厅和 HUD 使用地图数据与模型预览，人口分为军事和农民两行，训练/科技/建造队列保持一致。

验证：协议68项、复制52项、重连期限19项、非法命令172项通过；真实上海四进程86项通过，额外150 ms往返、5%丢包与乱序条件87项通过。HUD无头133项、两图Vulkan各137项通过。部署、网络量化及验证边界见 [联网验收](network-validation.md)。

## 阶段五：性能、发布与完整对局

- 对两图标准混编、满人口混战与集中行军分别记录显示帧和逻辑耗时；合并等价导航单元、后台生成施工网格、限制每步真实路径查询数，并复用128个原生特效实例。
- 2v2标准混编显示P95从21.99降至16.46ms，280人行军最大逻辑步从157.04降至13.06ms。P99和极限混战仍有长帧，全部结果及测量边界保留在 [性能报告](performance-0.6.0.md)。
- 实际发布包暴露并修复导航启动空路径死锁，以及Godot 4.6.3将普通空数组初始化的PackedStringArray错误转换为空生产列表的问题；改用原生构造器并通过ResourceSaver规范保存受影响资源。新清单与上海部署同步。
- 四端280人持续行军的本地与4%丢包测试各118项通过，房主分别29.977/29.996 TPS；本地逻辑P95为32.008ms，P99仍超过单步预算。丢包下完整快照实收7.3–7.7Hz，不能用15Hz发送目标代替实收频率。上海中继已同步通过验证的原生拥塞参数，原UDP24570服务保持运行。
- 最后审查修复了空闲农民快捷选择仍依赖旧阵营分组的问题。真实四玩家输入回归44项通过，按句点只轮换自己的空闲农民，跳过死亡及忙碌单位；无空闲农民时不会选择盟友或移动视角。
- Windows x64包包含EXE、PCK及中文操作说明。最终包通过真实EXE的95项资源/联网检查，以及原生Vulkan大厅/战场启动、截图和退出；完整正常经济Bot对局于561.60模拟秒（9分22秒）自然结束，13项验收通过，首次伤害为45秒。加速验收逐步保持1/30秒，不作为性能测量。其他成功样本包括9分53秒及11分29秒，6–10分钟仍是节奏目标，未宣称每局均达标。

发布验收保留最初失败、定位与最终成功的记录，详见 [发布包完整对局](release-match-validation.md)。构建输出为 `builds/AshenCrown-Windows-x64.zip`。
