# 0.7.3 闪退调查记录

调查日期：2026-09-10（北京时间）。本轮已经复现并修复一处多人客户端的已释放对象引用错误，也补充了退出、重开和日志保留验证。**目前没有证据证明这处脚本错误就是玩家报告的原生 EXE 闪退原因。** 玩家端实际发生退出时的版本、日志及 Windows 事件仍是确认同因所需的证据。

本记录只汇总可公开的结论、测试条件和数字。实际玩家日志、Windows 事件原文、转储及本地诊断 ZIP 留在忽略目录，不进入公开仓库。

## 已复现的选择对象生命周期错误

复现使用真实 Game 场景、多人客户端副本和本地选择操作：选中己方骑兵后，网络复制层移除该副本；节点释放后，`game.selection` 仍含该对象。此时刷新 HUD，或按 Shift 追加选择其他单位，会分别出现：

```text
Invalid access to property or key 'owner_id' on a base object of type 'previously freed'.
Trying to assign invalid previously freed instance.
```

首个错误来自 HUD 读取当前选择，第二个来自选择逻辑遍历已释放实例。复现日志同时记录了正常 `shutdown_begin`、`shutdown_complete`、`session_exit`，因此它证明了脚本生命周期缺陷，不能据此声称复现了进程访问冲突或原生引擎崩溃。

修复在对象仍有效时同步清理本地缓存：`Game.forget_entity_selection()` 从当前选择、全部编队和双击目标缓存中移除对象，死亡处理与 `MatchReplication._remove_replica()` 共用该入口。网络副本因离开视野而移除时只清理本地引用，不调用权威死亡结算，不改变金币、人口或战损。

相同的最小复现脚本在修复后已不再出现上述两种错误。专门回归 `tests/replica_selection_lifecycle_test.gd` 在 headless / Dummy 下 **48 项通过**，在真实 Windows / Vulkan / WASAPI 下同样 **48 项通过**；后者运行约 4.84 秒，退出码 0、stderr 为空。四种场景为单选骑兵、混合选择、敌人离开视野和施工建筑，分别在加入释放队列的同帧及实际释放两帧后访问 HUD、追加选择、编队、意图光标、指令路径提示、右键输入和框选完成入口。战争迷雾副本移除没有触发经济或死亡结算。现有网络复制组件回归也 **81 项通过**。

同时修复了施工目标消失后仍显示的旧“取消施工”按钮：动作保存稳定的建筑 `entity_id`，按下后交由命令入口和权威端验证，不再重新读取已经清空的当前生产建筑。上述回归通过按钮真实 `pressed` 信号验证此情况，确认无空对象访问，也不会把旧按钮的取消操作误发给后来选中的建筑。

四个独立客户端通过真实 ENet/DTLS 中继再次验证，共 **172 项通过**：非房主玩家鼠标选中、编队并指挥骑兵移动，房主正常击杀并仅释放一次 2 人口；客户端在同一个快照回调内确认选择、编队与双击缓存清空，继续刷新 HUD、Shift 点选其他单位、追加编队和右键移动，房主收到新指令。四客户端与中继的 stderr 均为空，记录为 `.local/network/live-local-6844429f`。

本地证据：

- `.local/crash-2026-09-10/repro-selected-death-stdio.log`：修复前的两种错误。
- `.local/crash-2026-09-10/repro-selected-death-after-stdio.log`：相同复现脚本的修复后输出。
- `.local/crash-2026-09-10/replica-selection-*`：两种驱动的正式回归日志；结果为 `artifacts/replica_selection_lifecycle_results.json`。

## Vulkan、声音、交战与重开验证

使用 Godot 4.6.3、Forward+ / Vulkan、WASAPI 原生声音、30 TPS、正常 `time_scale=1.0`，在真实地图上连续进行四轮交战、施工、退出大厅与重开。测试只提供初始单位和金币，不修改生命、伤害或冷却。

| 轮次 | 地图与编成 | 开始单位数 | 伤害事件 | 阵亡单位 |
|---|---|---:|---:|---:|
| 1 | 1v1 混编 | 104 | 372 | 69 |
| 2 | 2v2 混编 | 208 | 745 | 133 |
| 3 | 2v2 轻型军队满人口 | 280 | 1191 | 169 |
| 4 | 与上一轮相同的 2v2 满人口编成 | 280 | 1164 | 167 |

四轮合计 **92 项检查全部通过，3472 次伤害事件、538 名单位阵亡**。三种弹丸均有实际活动；每轮完成施工及导航重建，并在仍有弹丸和工作任务时退出。完整运行约 97.81 秒，测试进程退出码 0，stderr 为空。

最后两轮采用相同 280 人编成。返回大厅后的监测值为：

| 指标 | 第三轮后 | 第四轮后 |
|---|---:|---:|
| Godot 内存计数 | 229257573 字节 | 229262893 字节 |
| 显存计数 | 288027120 字节 | 288027120 字节 |
| 场景节点 | 386 | 386 |
| 孤立节点 | 0 | 0 |
| 资源计数 | 746 | 746 |

同构重开后的内存差为 **5320 字节**；显存、节点和资源计数一致。首次加载后的资源缓存增长与最后两轮的结果分开判断。这组有限样本没有显示每次重开重复保留整场资源的现象，也不能证明不存在长期泄漏。

另外两项 Vulkan / WASAPI 原生生命周期场景均正常退出，stderr 为空：声音关闭场景约 4.56 秒；单位关闭场景约 11.28 秒。

这些属于稳定性与资源释放检查。运行期间另有玩家游戏进程活动，未提供独占显卡条件；本轮没有据此承诺 280 人稳定 60 FPS，也不把此结果当成新的 P95/P99 帧时间测量。

本地结果：`stability-vulkan-runner.json`、`native-lifecycle-results.json`，均位于 `.local/crash-2026-09-10/`。

## 中继超时断开的独立问题

对连接超时进行 32 轮加速循环并保留一次实际 8 秒静默超时，旧关闭方式会留下原生 `TLS handshake error: -30464`。中继维护逻辑改为清理会话后使用 ENet 的正常断开，修改后的两次验证均 **254 项通过、stderr 为空、进程退出码 0**。

这是已验证的连接关闭问题。它说明原生传输层的退出路径需要规范处理，但没有证据把它认定为本次玩家客户端闪退的根因。

本地对照：`.local/network/timeout-lifecycle-926e7708/` 为旧行为；`timeout-lifecycle-76ea9277/` 与 `timeout-lifecycle-50f7423c/` 为正常断开验证。

## 日志保留与玩家本地收集

项目启用 `run/flush_stdout_on_print=true`，生命周期事件打印后立即刷新输出。Session 在启动、载入对局、结束、关闭场景和退出时记录带版本及 PID 的 `ASHEN_DIAGNOSTIC`；原生 Timer 每 15 秒记录一次有限的场景健康数据，不随游戏倍速加快。新诊断记录不打印邀请码、重连凭据或整个房间配置。

日志回归 **11 项通过**：测试进程仍存活时即可从磁盘读取启动和健康记录；随后中断该验证进程，记录仍保留且没有伪造正常退出标记。另一验证进程正常退出时有 `session_exit`，退出码为 0。它验证的是日志落盘与正常/异常退出标识，不是模拟引擎崩溃。所有验证采用单独 `--log-file`，避免轮转或覆盖玩家正在运行游戏的 `user://logs`。

最终 Windows 导出包的落盘验证结果保存在 `.local/crash-2026-09-10/logging-9b37c728/result.json`，11 项均通过，两个专用验证进程均已退出。

Windows 包内双击 `COLLECT_DIAGNOSTICS.cmd` 即可收集。默认只在“文档/AshenCrown-Diagnostics”创建唯一的时间目录和 ZIP；也可指定路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\collect_diagnostics.ps1 -GameDirectory . -OutputDirectory .\Diagnostics
```

收集范围是本游戏日志、近七天仅匹配 Godot/AshenCrown 的 Application Error / Hang / WER 事件、Windows/GPU/内存信息、安装包 EXE 版本和 EXE/PCK 的 SHA256。CrashDumps 只列本游戏/Godot 的名称、大小与时间，不复制内存。脚本不上传，不改系统或游戏设置，不读取 `.env` 和凭据，不终止正在运行的游戏，不扫描其他用户数据目录。

真实收集验证得到 5 份游戏日志、上述 2 条事件及 2 个转储的元数据，零警告；EXE/PCK 哈希与原文件重新计算一致，ZIP 不含转储、凭据、玩家设置或整个安装包。收集器进程已退出。日志和事件可能包含本机路径、连接地址或房间信息，玩家可先查看 ZIP，再手动回传并说明出错时的操作、单人/多人模式及大概时间。

该工具让下次异常保留可比较的证据。当前结论应分别表达为“已修复可复现的选择引用错误”和“原生闪退原因仍待对应玩家日志确认”，不能把压力测试未复现写成所有闪退已解决。
