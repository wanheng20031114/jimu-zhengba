**《积木争霸》七种新单位建模、试装与逐项验收计划**

**一、制作范围与推进规则**

本计划采用已经确认的数值，沿用现有低多边形风格，完成七种单位的真实三维模型、动画、玩法、生产入口、战争图鉴、沙盒展示及联机同步。

制作顺序固定为：

**盾卫 → 战象 → 轻骑兵 → 工程兵 → 牧师 → 重型火炮 → 三管短炮。**

严格遵守你提出的逐单位验收要求：

1. 每次只制作当前单位。
2. 我先完成建模、视觉检查、动画、完整试装和相关测试，自主修正发现的问题。
3. 向你展示当前单位的真实游戏画面、动作效果、数值和测试结果。
4. 停留在当前单位，等待你的明确意见。
5. 你要求修改时，继续修改当前单位并重新展示。
6. **只有你明确表示当前单位通过、可以继续，才开始下一个单位。**
7. 对当前单位的局部评价、补充要求或暂未回复，都不视为允许进入下一单位。

当前单位内部的建模、修正、测试不反复请求许可。后续单位可以保留在计划中，但不提前制作其模型、动画或玩法。

电脑对手本轮**保留原有招募阵容**。补充对新单位的分类识别、威胁判断和克制响应，保证玩家使用新单位时，正常遭遇战能够运行。

进入实施阶段后，先将本计划保存到项目文档，并维护“当前单位、当前版本、待修改事项、验收结论”的简短记录。

**三、七个单位的制作内容与专属验收标准**

**第1阶段：盾卫**

目标是做出具有明显重装感的大盾步兵，同时保留现有角色的头身比例、金属质感和阵营色。

建模内容：

- 以剑士的人体比例作为参照，身体略宽，站姿更稳。
- 胸甲、背甲、肩甲和护胫形成完整的防护层次。
- 使用接近肩部至小腿高度的大盾，具有厚度、包边、内侧握把与支撑带。
- 盾牌通过左手和前臂连接；右手持短剑。
- 头盔具有清晰的眼部开口，五官位置与剑士的头部基准对齐。
- 阵营色集中于盾面和衣料，金属部分保持材质本色。

动画内容：

- 待机：轻微呼吸，盾牌稳定。
- 行走：步幅较短，身体起伏克制。
- 攻击：盾牌保持防护姿态，短剑从盾侧刺出或短挥。
- 攻击前摇0.30秒，与实际近战命中时刻一致。
- 死亡沿用现有倒地与淡出流程，检查大盾不会悬空。

试装与验收：

- 接入兵营训练、人口、生产队列、图鉴、头像和沙盒。
- 与剑士、长矛兵并排查看，确认大盾轮廓清楚。
- 检查近距离盾牌厚度、手部连接和眼部位置。
- 正常战场缩放下仍能辨认其盾牌与重装身份。
- 弓箭手对其基础伤害为4；盾卫不获得未设计的格挡、嘲讽或击退能力。
- 与骑士对向接近时，检查是否出现此前的突然退步或转身问题。

完成后提交盾卫的展示与测试结果，等待你同意后进入战象。

**第2阶段：战象**

目标是制作体型明显大于战马、动作沉重的骑兵单位，并严格保持360生命、26单体近战攻击的较低数值版本。

建模内容：

- 独立制作象身、四肢、象头、象鼻、象耳、象牙和尾巴。
- 象鼻使用少量可独立转动的分段，保证低多边形外观。
- 灰色象皮构成主体，额头和胸部使用局部护甲。
- 背部设置阵营色披布、简洁鞍具和一名骑手。
- 骑手保持现有角色的头部与五官比例，不附带第二套攻击。
- 象牙和披布作为外形装饰，不额外扩大攻击范围。

动画内容：

- 待机：象耳缓慢摆动，象鼻轻摆，身体有呼吸起伏。
- 行走：四足交替承重，身体缓慢起伏。
- 攻击：象头前压、象牙顶击，辅以前脚踏地。
- 攻击前摇0.55秒，单次只向锁定目标结算伤害。
- 踏地尘土只用于表现，不产生范围伤害或击退。
- 死亡检查大体型倒地是否穿入建筑、悬浮或错误遮挡血条。

试装与验收：

- 骑兵分类从数据进入统一伤害计算，不按模型外观判断。
- 未升级长矛兵每次造成24伤害，剑士每次造成12伤害。
- 在主目标旁放置两个敌人，确认它们不会受到波及。
- 测试围攻、转向、狭窄道路、兵营出口和建筑边缘接敌。
- 血条、选择圈、鼠标点选和碰撞体积与象身匹配。
- 与剑士、骑士同场查看，确认尺寸关系清楚且不遮满画面。

完成后等待你同意，再制作轻骑兵。

**第3阶段：轻骑兵**

目标是通过装备与轮廓体现轻快感，并准确呈现6.8速度和20视野。

建模内容：

- 沿用现有战马的风格与基本比例，制作独立的轻装变体。
- 移除厚重马铠，保留缰绳、马鞍和少量阵营色鞍毯。
- 骑手使用轻胸甲或皮甲、开放式轻头盔与短兵器。
- 骑手五官不能被头盔和衣领挤到面部下方。
- 与骑士并排时，能直接看出马身装甲和骑手装备的差别。

动画内容：

- 四肢步态与6.8移动速度协调，减少滑步。
- 骑手随马背轻微起伏，持兵器的手保持稳定。
- 攻击采用短幅挥砍，前摇0.20秒。
- 不附加新的冲锋增伤、冲撞或击退机制。

试装与验收：

- 同起点、同路线比较骑士与轻骑兵，确认轻骑兵实际更快。
- 战争迷雾中比较视野边界，确认20视野真实生效。
- 验证其没有继承骑士的对攻城器 +11。
- 长矛兵对其基础伤害为25。
- 重点复测高速对向接敌、追击逃跑目标和接近时转向。
- 电脑将其识别为骑兵，继续使用原有兵种应对。

完成后等待你同意，再制作工程兵。

**第4阶段：工程兵**

目标是做出职业特征清晰的维修单位，并建立可供后续牧师复用的支援流程。

建模内容：

- 使用与现有步兵一致的人体比例。
- 配备皮革围裙、工具包、腰带和锤子。
- 服装保留阵营色，工具使用木柄与金属锤头。
- 外形重点是工具和工作装备，避免与农民混淆。
- 锤子握持点和腕部转轴明确，能够完成敲击动作。

动画内容：

- 待机与行走使用常规步兵动作。
- 维修时面向机器，身体稍向前倾，周期性敲击。
- 每秒一次有效维修，恢复5生命。
- 使用少量敲击火花和已有适合的工具音效。
- 自卫攻击使用锤子，攻击前摇0.30秒。

维修行为：

- 只维修存活的友方攻城器，包括盟友的机器。
- 战象不属于可维修目标。
- 不修建筑、不采矿、不承担施工，不消耗金币。
- 目标可以在被维修时开火。
- 工程兵必须停下才能维修；机器驶出工作距离后暂停恢复。
- 手动指定目标时，工程兵会跟随并重新靠近。
- 同一目标只能由一名工程兵有效维修，其他工程兵优先寻找别的受损机器。
- 满血、目标死亡、停止命令或切换任务时，释放维修占用。

试装与验收：

- 选中工程兵，右键受损友方攻城器可以维修。
- 恢复100生命需要20秒有效工作时间。
- 零金币时维修仍能正常进行，金币不会减少。
- 两名、五名工程兵同时操作同一机器，恢复速度仍为5生命／秒。
- 目标移动、工程兵死亡、目标死亡、取消指令后，不出现残留恢复或永久占用。
- 验证攻城器一边开火一边接受维修。
- 联机中只有主机修改生命，其他客户端同步工作动作与血条。

完成后等待你同意，再制作牧师。

**第5阶段：牧师**

目标是完成具有清晰治疗动作和GPU粒子效果的高价支援单位，同时保留3点挥拳攻击。

建模内容：

- 使用长袍、腰带、书袋和少量阵营色装饰。
- 双手保持空闲，能够表现祈祷、施法和挥拳。
- 头部沿用现有人物比例，五官放在正确面部高度。
- 衣领、兜帽或头饰不能遮住整个面部。
- 袍摆分出必要的活动部分，行走时腿部与衣料关系自然。
- 首版采用刚性分件动画，不增加布料物理模拟。

动画与粒子：

- 待机：轻微呼吸与手部自然摆动。
- 行走：小步前进，袍摆适度摆动。
- 治疗：双手抬起，身体轻微前倾，完成一次明确的施法动作。
- 第一轮在0.6秒时恢复10生命，后续每秒一次。
- 攻击：短距离挥拳，前摇0.25秒，基础伤害3。
- 治疗和挥拳互斥，不能同时播放或同时结算。

粒子使用原生 `GPUParticles3D` 与 `ParticleProcessMaterial`，在保存的场景中配置。手部产生暖金色光点，受治疗单位出现短暂、向上飘散的光点和柔和光晕；粒子数量保持克制，实际恢复逻辑独立于粒子播放。[Godot 官方文档](https://docs.godotengine.org/en/4.6/classes/class_gpuparticles3d.html)

治疗行为：

- 可以治疗友方步兵、骑兵、农民和其他牧师。
- 工程兵也属于可治疗目标。
- 不治疗攻城器、建筑、阵亡单位或自身。
- 可以在战斗中治疗，不消耗金币或法力。
- 自动治疗优先选择范围内生命比例较低的有效目标。
- 手动指令优先于自动选择。
- 同一目标同时只能接受一名牧师的主动治疗。
- 移动会中断未完成施法；切换目标不能刷新恢复频率。
- 目标满血后完成当前支援命令，并处理后续排队指令。

学院接入：

- 增加牧师招募入口，保留现有科技入口。
- 训练队列与研究队列沿用现有独立计时，可以同时进行。
- 牧师按钮放在学院操作第一页，科技超过可显示数量时分页。
- 正确处理人口预占、训练取消退款和学院被摧毁时的队列清理。

试装与验收：

- 验证0.6秒前摇、每次10生命、后续1秒间隔。
- 检查停止、移动、换目标和反复点击无法加速治疗。
- 验证多牧师不叠加、其他牧师可被治疗、主动自疗无效。
- 攻击确实为挥拳，伤害通道为近战。
- 同时检查图鉴中的治疗动作与战场中的真实治疗。
- 在多个牧师同时施法时检查粒子遮挡、帧时间、迷雾可见性和退出清理。

完成后等待你同意，再制作重型火炮。

**第6阶段：重型火炮**

目标是做出比普通加农炮更沉重、射程更长、单发威力更高的火炮。

建模内容：

- 使用更长、更粗的炮管与加固炮架。
- 2026-09-13补充确认：炮管进一步加长、加粗，车体保持紧凑；外伸炮管允许穿过周围物体，单位碰撞／占位半径仍为1.15，不随炮管扩大。
- 采用四轮厚重底盘，与普通加农炮形成明显区别。
- 炮口具有可见内腔和厚度。
- 木材、钢铁、金属包边与阵营色延续现有风格。
- 炮管设置独立转轴和明确炮口标记。

动画内容：

- 移动时四轮正确转动，车体保持稳定。
- 开火前有短暂准备，前摇0.45秒。
- 炮管产生明显后坐，随后缓慢复位。
- 完整开火与装填节奏匹配4.2秒攻击间隔。
- 炮口火光、烟尘与炮弹释放位置一致。

玩法接入：

- 使用现有单体炮弹逻辑。
- 100基础攻击，对建筑额外100。
- 基础射程14，研究后15，最小射程3.5保持不变。
- 移速1.8，260生命，价格500。
- 不增加爆炸范围伤害。

试装与验收：

- 与普通加农炮并排比较尺寸、射程和攻击节奏。
- 验证研究前后始终比普通炮多1射程。
- 对10护甲建筑每发造成190伤害。
- 对战象每发造成97伤害。
- 贴身目标不能被攻击，后排保护具有实际作用。
- 检查炮管转向、后坐、墙边开火、出口通行和弹道同步。

完成后等待你同意，再制作三管短炮。

**第7阶段：三管短炮**

目标是让“三根短炮管”和“每轮攻击三个不同目标”的特点在模型、动画与战斗中一致。

建模内容：

- 三根并排短炮管，炮口能够分别辨认。
- 每根炮管具有独立后坐部件与炮口标记。
- 使用比重型火炮轻巧的两轮炮车。
- 保留紧凑底盘、金属连接件和阵营色面板。
- 不把模型做成长炮管火炮的缩小版。

攻击过程：

1. 开始一轮攻击时，锁定主目标。
2. 以朝向主目标的方向为中心，在正面90度扇形内寻找额外目标。
3. 额外目标必须在有效射程内、存活、可见且属于敌方单位。
4. 主目标优先，其余目标优先步兵，再按距离、实体编号稳定排序。
5. 最多选三个不同目标，每个目标只分配一发。
6. 三发释放时点为攻击开始后的0.25、0.35、0.45秒。
7. 一轮攻击间隔为2.4秒，不按每根炮管分别刷新。
8. 只有一个或两个目标时，只播放对应数量炮管的开火动作。
9. 某目标在该发释放前失效，则取消对应炮弹，不补射到其他已选目标。
10. 停止命令或本体死亡取消尚未发射的炮弹；已发射炮弹沿用现有结算规则。

伤害与目标限制：

- 每发18远程攻击，对步兵额外12。
- 没有溅射，同一目标不会在一轮中吃到三发。
- 额外目标只选择单位；建筑只有作为主目标时才能承受一发。
- 对建筑没有额外伤害。
- 射程7、最小射程1.0，不参与加长炮管科技。

试装与验收：

- 分别摆放1、2、3、5个敌人，核对炮弹数量与命中对象。
- 测试扇形边缘、射程边缘、贴身目标和目标中途死亡。
- 基础单发伤害：剑士28、长矛兵29、盾卫23、骑士11、弓箭手13。
- 检查三根炮管是否分别后坐，空置炮管是否保持静止。
- 检查反复攻击指令不会绕过整轮冷却。
- 在大量炮弹同时存在时，不能因为视觉对象池容量不足而漏算伤害。
- 完成本单位测试后，进行七种新单位共同参战的整体验证，再交你验收。

**五、视觉检查、测试与交付**

**每个单位都执行三轮视觉检查**

第一轮检查静态模型：

- 正面、背面、左右侧面、四分之三视角和俯视角。
- 人物眼睛、鼻子、嘴与下巴的相对位置。
- 头盔、衣领和肩甲是否遮住五官。
- 胸背护甲是否有明确厚度与层次。
- 武器、盾牌、缰绳、工具与手部是否连接。
- 脚、马蹄、象足、车轮是否接触地面。
- 木材、皮革、金属与布料是否容易区分。
- 不同阵营颜色是否只改变指定的衣料与纹章区域。

第二轮检查动画：

- 在待机、行走、攻击、维修或治疗中观察连续动作。
- 采样准备、接触／释放、最大幅度、收势和循环衔接关键帧。
- 检查武器穿过身体、盾牌切入脸部、手掌离开握把、象鼻折断、车轮倒转等问题。
- 检查停止、转向、攻击取消和死亡时的过渡。
- 炮口标记必须跟随炮管，手部粒子必须跟随施法动作。
- 镜头移出再移回、暂停再继续后，动画不能跳回错误姿态。

第三轮检查真实战场：

- 正常游玩缩放、近距离观察和较远缩放。
- 与现有单位同屏比较尺寸和风格。
- 在草地、道路和建筑旁检查材质与阴影。
- 检查选择圈、血条、点击范围和队伍颜色。
- 检查大盾、象身和火炮是否遮挡过多关键战场信息。
- 图鉴中的效果与批量渲染战场效果必须一致。

每轮使用实际渲染画面进行检查，发现问题后修改并重新查看相关角度或动作。视觉结论不以“资源成功加载”代替。
